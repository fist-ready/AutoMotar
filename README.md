# AutoMortar · PUBG 地图平面测距

使用 C++17、Win32、GDI 和低级键鼠钩子，在游戏上方显示背景透明、可穿透的菜单、标点与连线。支持按地图保存 0–4 档比例尺，以及关闭地图后保留上次距离。技术路线参考本地 `refer_repo/PUBG_MAP`；本实现独立编写，参考仓库未修改。设置界面使用原生 Win32 对话框，不需要 MFC。

## 直接运行

编译好的程序：`bin/Release/AutoMortar.exe`。

双击 EXE 后会打开主窗口，显示运行状态、操作说明，以及“选择本局地图”“菜单外观与设置”入口。点击右上角关闭或“收起到托盘”后，程序继续运行；双击托盘图标，或托盘右键“打开主窗口”，即可再次打开。重复双击 EXE 也会唤起已运行实例的主窗口。需要彻底退出时使用“退出程序”或托盘“退出”。

1. 将 PUBG 设置为**无边框窗口模式**，运行程序。默认只在前台进程为 `TslGame.exe` 时显示覆盖层。
2. 每局按 **F5** 选择地图并“开始本局”：程序缩放复位为 0 档、载入此地图保存的比例尺、清除上一局的距离。此时游戏地图也应处于最小缩放。
3. 用 **M** 打开地图。若实际地图已经打开，面板却显示“地图已关闭”，按 **F8** 校正。程序通过 M 推断地图状态。
4. 首次可以按 **F7**，用 **Alt＋右键**依次点地图有效区域的左上、右下角。区域宽高至少 100 像素；未设置时使用整个游戏客户区。
5. 将地图缩放到合适大小。如果此档已有比例尺，可以直接测距；否则按 **F6**，用 **Alt＋右键**点击一段已知长度网格线的两端。默认代表 **100 米**，像素间距至少 20。标定完成立即保存，无需额外点击保存按钮。
6. 用 **Alt＋右键**先点自己，再点目标。菜单显示水平距离，并在两点间画线。
7. 按 M 关闭地图后停止取点，距离数字作为“上次结果”显示 **3 秒**，随后整个覆盖菜单隐藏。再次按 M 开图后恢复显示，并继续使用当前缩放档位和已保存比例尺。隐藏只影响显示，不会删除距离或标定数据。

程序刚启动且地图未打开时，游戏内不显示覆盖菜单。地图打开时菜单持续显示；F8 手动关闭和 Esc 关闭测距也遵循 3 秒隐藏规则。游戏切到后台立即隐藏，倒计时仍继续；短时间重复关闭不会延长计时。

建议标定多格以降低取点误差：托盘右键 → 设置，将“标定线段长度”改为 500，再点击五个已确认 100 米网格的两端。必须先确认当前网格的实际长度，避免把粗网格误作细网格。

### 热键

| 操作 | 功能 |
|---|---|
| F5 | 选择地图并开始本局；缩放复位 0 档、清除上次距离 |
| F10 | 只将程序记录的缩放复位为 0 档，保留比例尺和上次距离 |
| M | 推断地图打开/关闭并切换启停状态 |
| F8 | 手动切换启停，纠正 M 状态失步 |
| F6 | 标定当前地图当前缩放档，完成后自动保存 |
| F7 | 设置地图有效区域 |
| Alt＋鼠标右键 | 记录当前步骤所需的点 |
| F9 | 清除取点和上次距离；保留所有比例尺 |
| Esc | 关闭测距，保留比例尺与上次距离 |
| 空格 | 清除两点，应对地图重新居中；保留上次距离 |

所有按键继续传递给游戏。F5–F10 如已绑定其他游戏功能，需要先调整游戏绑定；本版尚未提供自定义热键。Alt＋右键仍会执行游戏中的路线标记。

### 缩放跟踪与配置复用

- 采用用户实测约定：最小缩放为 **0 档**，最多放大四次至 **4 档**。
- 仅当前台是游戏、地图状态已打开、鼠标位于地图有效区域时统计垂直滚轮。向上放大、向下缩小，每 120 wheel delta 为一档；支持多档事件与不足一档的小事件累计。
- 达到 0/4 边界后继续向外滚不会增加隐藏计数，反向一格就能正常返回。
- 切档后自动载入该档比例尺；未标定档位只提示标定，不推算未知档位。
- 每档标定完成自动写入 EXE 同目录 `AutoMortar.ini`，按地图、客户区分辨率、DPI 分开保存。下一局选择相同地图与显示配置即可复用。
- M 关/开地图、F8、Esc 不重置缩放；程序重启和 F5“开始本局”从 0 档开始。
- 失焦时覆盖层隐藏，地图状态、缩放和上次结果保留；游戏窗口移动不会清除保存的比例尺。分辨率或 DPI 变化时切换到对应配置，不覆盖其他显示配置。
- 拖动、缩放、关图、失焦会清除屏幕点，避免混合不同视图的坐标；上次完成的距离独立保留，并标明为历史结果。
- F6 重标定可以覆盖当前档的旧比例尺。修改标定线段长度只影响下一次标定，已经保存的比例尺仍然有效。

例如，海岛 1920×1080、96 DPI 的比例尺保存在 `[Scale.Erangel.1920x1080.96]`，`Zoom0` 至 `Zoom4` 分别以米/像素存储；没有测过的档位不会自动填值。最后一次选择的地图通过 `LastMap` 保存，程序重启仍建议用 F5 确认本局地图。

**状态纠正：**如果滚轮计数与游戏不同步，先将游戏地图一直缩小到最小，再按 **F10**。F10 只复位程序计数，不会替你滚动游戏地图。M 状态失步则按 F8 校正。不要在游戏地图还处于放大状态时直接复位后继续标定。

M 的状态是键盘推断，无法识别聊天输入、其他关闭地图方式或游戏未接受的按键。若只改变游戏内部 UI 缩放而客户区大小/DPI 未变，也可能需要用 F6 重标定对应档位。

## 不启动游戏的演示

在项目目录用 PowerShell 运行：

```powershell
.\bin\Release\AutoMortar.exe --demo
```

演示地图在 0 档每格 80 像素，代表 100 米。按 F8 → F6 → 用 Alt＋右键选择同一条网格线上相邻两个交点 → 用 Alt＋右键选择绿色与黄色十字。结果应为 **500 米**。演示地图也支持五档缩放，可验证各档标定保存与切换复用；演示倍率只用于演示，不代表 PUBG 实际倍率。

选择标定点时避开覆盖菜单，建议选择地图右侧网格。演示使用独立的 `AutoMortar.demo.ini`；如果修改了演示标定长度，应选择对应格数。关闭演示窗口会退出程序。正常模式和演示模式不能同时运行。

## 设置和文件

- 主窗口“菜单外观与设置”或托盘右键“设置”：修改已知长度、目标进程文件名、面板左上角 X/Y，以及以下外观参数。

| 设置 | 默认值 | 范围 |
|---|---:|---:|
| 正文字号 | 13 | 9–28 |
| 距离数字字号 | 28 | 16–64 |
| 额外行距 | 1 | 0–16 |
| 菜单宽度 | 340 | 220–800 |

字号、行距和宽度以 96 DPI 下的像素为基准，随显示器 DPI 缩放。菜单背景透明，高度按字号、行距和自动换行计算；可以通过减小字号、行距和宽度减少占用。设置保存后应用于下一次菜单显示，并在程序重启后保留。修改菜单外观不影响已保存的地图比例尺。

- 面板位置相对于游戏客户区，使用物理像素，超出范围时自动限制在窗口内。
- 配置保存在 EXE 同目录的 `AutoMortar.ini`。目录需要可写权限。
- 双屏情况下，根据前台目标窗口的客户区定位覆盖层，支持负桌面坐标。
- 菜单随 DPI 调整文字大小；测距点和比例尺统一使用客户区物理像素。

## 编译与测试

需要 Visual Studio 2022 C++ 桌面开发工具、Windows SDK、CMake、PowerShell 7。无需 MFC、OpenCV 或 AHK。

```powershell
.\build.ps1
```

脚本生成 `build/AutoMortar.sln`、编译 Release 版并运行 CTest。也可以在 Visual Studio 打开根目录的 CMake 工程或生成的解决方案。MSVC 运行库静态链接。

```powershell
# Debug 编译与检查
.\build.ps1 -Configuration Debug

# 重跑已编译的检查（先退出已运行的 AutoMortar）
ctest --test-dir build -C Release --output-on-failure

# 使用程序自己的 GDI 绘图代码生成示意图，输出到当前目录
.\bin\Release\AutoMortar.exe --render-preview
```

检查内容：

- 数学/状态：标定计算、关图保留结果、闭图忽略输入、五档复用、滚轮上下限与小事件累计、重置、新局与地图/显示配置隔离，以及 3 秒隐藏边界、重开取消隐藏、重复关闭不延长计时。
- Windows 冒烟检查：覆盖窗口属性、透明背景像素、键鼠/前台窗口事件钩子、设置/地图选择/主窗口控件、主窗口关闭只隐藏、字号与宽度对实际布局的影响、字体缓存预热后连续绘制 100 次无 GDI 对象数量增长，以及临时 INI 文件中的比例尺/外观参数读写和损坏值处理。
- 菜单示意图：`overlay-preview.png`，由真实绘图函数输出并转换格式，背景是演示网格。

上述检查不替代 PUBG 实机验证。尚未验证游戏中的热键接收、无边框覆盖效果，以及不同显示器缩放组合。独占全屏不属于本版保证支持的显示模式。

## 范围

当前只计算水平距离，不提供高差补偿、弹道校准或自动识别地图网格。覆盖层显示的是计算结果，尚未验证为游戏迫击炮的实际设置值。程序读取前台窗口的进程名称、窗口位置和用户输入，不读取游戏内存。

实现分析见 [docs/architecture.md](docs/architecture.md)。
